## 2. 音频来源与声音设计

本批音频由本次交付的 Python 脚本原创合成，没有下载音乐，没有使用第三方采样、音色库或既有游戏音效，也没有拷贝工程旧占位音。旋律、和声与编排均在脚本中直接定义，未改编指定曲目。音频的来源记录即此文档和完整生成源文件；未引入需要另行取得许可的第三方音频文件。

视觉采用轻扁平像素夜港，声音对应少量、清楚、柔和的像素音色。主音色使用有限谐波的三角波、柔化脉冲和正弦低音；不用刺耳全频方波，不加入强鼓点或噪声冲击。取箱音突出短反馈；出港上行；通关保留简短旋律；无效操作主动降低音量与音高，表达“当前不能操作”。

背景音乐为 80 BPM、4/4、8 小节，共 24 秒。和声为 Fmaj7 / G6 / Em7 / Am7 的两轮，第二轮有旋律回应。音符事件使用平滑起音与释放，允许释放尾音跨越循环边界；延迟也按循环缓冲区计算，使开头已包含上一轮尾音。文件没有烘焙全局淡入/淡出，也没有在结尾拼一段静音。

循环范围为采样帧 **0 至 1,058,400（结束值不包含）**；播放时间范围为 **[0, 24) 秒**。不应额外复制最后一帧或把循环终点挪到 23.999 秒。左右声道首尾样本差分别为 52 / 64 PCM16 单位（约 0.001587 / 0.001953 FS），小于内部最大相邻样本差 274 单位（0.008362 FS）。这是连续波形的一步采样变化，不要求首尾两个不同时间点的样本数值相等。

五个短音效的首尾采样均为 0，使用平滑包络，避免硬截断带来的起止爆音。全批没有 PCM 削波样本，峰值均低于 -3 dBFS。RMS 数值仅表示文件平均能量，不能当作听感响度或 LUFS 测量。

## 3. 字体来源、许可与边界

本次复用工程现有的 Noto Sans SC 重命名 UI 子集，字体内 family/full/PostScript name 均为 `PortCargoUI`，字重 Regular。保留文件内 Adobe 2014–2021 版权信息、Reserved Font Name `Source` 及 SIL OFL 1.1 许可。完整原文以随包 `OFL.txt` 为准，分发字体时随包保留该文件及字体内元数据。

这是 **330 个 Unicode 码位、362 个 glyph 的子集**，其中包含 224 个中文码位，**不是完整中文字体**。字体名称采用已有项目的 `PortCargoUI`；本次没有进一步改名、扩字或修改字形。标题和正文可复用此字体，关卡号、数量、按钮文案保持动态文本，不需要制作数字图片。字体本身为无衬线字体；像素风由图形、图标与间距建立，中文正文优先保证清晰度，不能把它宣称为新制作的点阵中文字库。

本次只读扫描 `Assets/PortCargo/Scripts/Runtime` 下 **15 个 C# 文件**，从字符串字面量提取到 **200 个不同中文字符**，TTF cmap 缺字为 **0**。扫描排除注释和字符字面量，支持项目内普通、逐字与插值字符串；报告中保留了扫描文件和 SHA-256，便于后续复核。

覆盖结果仅针对这次扫描到的 Runtime 字符串。它不覆盖未来文案、外部数据、本机用户名、其他语言、Editor 文案，也不能证明当前 TMP 图集已经具有所有字形。若新增文案，需先检查 cmap；TTF 缺字时须取得合适的完整字体/扩展子集并核对许可，不能仅将缺字字符加入文本列表。Unity 接入时按最终文案重建静态 TMP 字库并检查实际显示；本次没有生成 `.asset` 或 `.meta`，没有重建项目 TMP 图集。

## 4. 重制方法

脚本运行环境为 Python 3.10+、numpy、fontTools；本次使用 Python 3.10、numpy 1.23.5、fontTools 4.41.1。[`requirements.txt`](../02_可编辑源文件/Audio/requirements.txt) 列出依赖，生成过程无需联网。首次安装 Python 依赖可能需要联网。解压后进入交付根目录，再运行：

```sh
python3 -m pip install -r "02_可编辑源文件/Audio/requirements.txt"
python3 "02_可编辑源文件/Audio/generate_audio_and_font_manifest.py"
```

输出位置根据脚本所在目录推导，只写本资产包的 Audio、Fonts 及音频字体 manifest，**没有硬编码本机目录，也不依赖原 Unity 工程才能重建音频**。默认用包内 TTF/OFL/字表检查字体 cmap 和哈希，并明确记录 `runtime_scan_status: skipped_no_project`；原工程缺字扫描不会伪记为“0 个缺字”。若包里已有交付时的扫描结果，它会保存为 `reference_runtime_scan`，标注为历史证据、未重新检查。

需要基于接收方当前 Unity 工程重新检查 Runtime 中文覆盖时，显式传入只读工程路径（替换示例路径）：

```sh
python3 "02_可编辑源文件/Audio/generate_audio_and_font_manifest.py" --project "/你的工程目录/PortCargo"
```

指定目录不存在或没有 `Assets/PortCargo/Scripts/Runtime` 时，报告写明跳过原因，仍完成包内字体检查。包内字体已经存在时，指定工程不会悄悄覆盖它；只有包内三件套缺失且传入工程有对应源文件时才补齐。来源字体与包内字体不同时，会在 `matches_source_hash` 中如实报告。

只需重建音频时，使用下面命令；该模式只依赖 numpy，无需字体文件或 fontTools：

```sh
python3 "02_可编辑源文件/Audio/generate_audio_and_font_manifest.py" --audio-only
```

脚本不会调用 Unity 或写入 `Assets`。重跑会覆盖本包同名音频和音频字体 manifest；完整模式还会更新字体审计文件，`--audio-only` 则把本次 manifest 的字体检查标记为跳过。需要保留调音版本或原始报告时，先复制输出目录。

重制参数在文件顶部，包括采样率、80 BPM、峰值目标及 `SEED=20261016`。本版没有随机过程，种子仅为未来扩展预留；结果在本次环境中重复运行 SHA-256 一致。跨不同 numpy 或平台版本时浮点舍入可能影响最后一位采样，宜重新检查 manifest。

需要改音效时编辑 `render_effects()` 中的音符 MIDI 号、起始秒数、时长、音色、相对增益与音高弯曲；需改音乐时编辑 `harmony` 和 `melody` 数组。要保持 24 秒循环，保留 8 小节与 80 BPM；改变速度或小节数后按脚本自动重新计算帧数。不要手工剪掉跨边界释放尾音。

## 5. 后续接入与混音建议

下列为接入建议，此次交付未实际修改 Unity 设置。

- SFX 以 2D 声音导入，保留单声道和采样率。短音效可用 PCM / Decompress On Load，具体以目标平台内存预算为准。
- BGM 保留双声道并开启循环。母版建议先用 PCM 验证接缝，再按平台要求压缩；有损编码可能改变边界或产生编码延迟，不能用母版检查代替压缩后复听。
- 初始试听可设 SFX 总线 0.8、BGM 总线 0.7；文件自身已经让音乐轻于交互声，后续以设备实听调整。不要为了把每个音的峰值拉成一样而放大柔和的无效操作音。
- 音乐播放与停止建议运行时做 40–80 ms 短淡变，循环本身保持连续。不要在每次循环边界添加淡入淡出。
- 取箱快速连点需控制叠加数量/触发节奏；保留现有 `FeedbackPlayer.Reject()` 的 150 ms 防重入，避免长按叠声。菜单音仅用于明确点击，不用于每帧或触碰悬停。
- 音效、音乐开关沿用现有设置与持久化；此批素材不新增玩法逻辑，也不应以音效播放结束驱动取箱或通关提交。
