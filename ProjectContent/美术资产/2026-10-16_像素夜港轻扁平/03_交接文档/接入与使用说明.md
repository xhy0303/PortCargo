## 3. 风格边界与允许修改的内容

采用深蓝夜港底色、蓝紫远景、暖黄灯光、明亮功能色和浅色文字。港口插画提供环境气氛，交互区保持更平、更简洁的表面；按钮和面板用薄边、少量切角和克制的亮边表达层级，避免恢复厚重浮雕或长投影。

四类货物的语义固定为：

| 逻辑货类 | 颜色方向 | 必须保持的纹样 | 使用范围 |
| --- | --- | --- | --- |
| R | 红 | 竖条 | 棋盘、当前需求、预告、暂存、飞行影像、教学和首页示意 |
| B | 蓝 | 圆点 | 同上 |
| G | 绿 | 斜线 | 同上 |
| Y | 黄 | 十字 | 同上 |

可以在同一方向内调整颜色明度、背景细节和装饰位置，但不能把 Y 改成星星、把 B 改成波浪，或在小图标里省掉纹样。不能用颜色单独代表货类。四种货箱应保持相同留白、视觉面积和纹样可读性。

文本、数字、进度、装载量、关号、无尽程数和按钮文案继续由 TMP 生成。标题“港口装箱”也采用动态 TMP 文本，本包没有要求把标题变成固定图片。不要从参考图裁出带“第 06 关”“0/3”“免费 1 次”的位图作为运行时组件。

## 4. 源文件怎样编辑和重建

### 4.1 精确绘制的界面组件

Cargo、UI、Icons、Tutorial 等精确组件采用可编辑 SVG，并导出 PNG。SVG 保存形状、坐标和色值，PNG 是 Unity 使用的交付格式。SVG 不作为要导入 Unity 的组件，也不要求安装 SVG 导入插件。

精确组件由 `build-components.cjs` 重建，通用空船由 `build-ship.cjs` 重建。两者需要 Node.js 和 `sharp`；脚本先查找可用的 `sharp`，也可通过 `SHARP_MODULE` 指定已安装模块路径。脚本不依赖本机绝对路径；请先安装 sharp 或显式设置 SHARP_MODULE。准备好依赖后，在本包副本根目录执行：

```sh
node "02_可编辑源文件/build-components.cjs"
node "02_可编辑源文件/build-ship.cjs"
```

这两条命令会覆盖包内对应同名源文件、PNG 和分项清单；保留人工修订前先备份或纳入版本控制。合并总清单和构图预览的步骤需按最终交付入口执行，不能把重建分项误认为整包索引已同步。

修改步骤：

1. 在包副本中找到 `02_可编辑源文件` 对应源文件，记录修改原因与涉及资产 ID。
2. 直接编辑 SVG，或修改 `build-components.cjs` 中对应组件的形状与参数。若该 SVG 由脚本生成，应同步修改脚本，避免下次重建覆盖人工调整。
3. 使用源目录所提供的重建入口重新导出。运行前先检查脚本内的输出路径和依赖说明，输出必须仍指向本包副本，不能写入现有游戏工程。
4. 将重建后的 PNG 与旧版对比，检查透明边、像素对齐、图案、状态与 9-slice 边界。
5. 同步更新清单中该文件的尺寸、边界、来源与哈希等字段，并重建相关预览。

常见组件基准包括 128 像素货箱、64 像素图标、192×64 按钮；这些是源文件的构图基准，不是强制运行时显示尺寸。每个资产的最终规格仍以清单为准。不能将所有图标统一拉到按钮宽高，也不能把方形货箱强行拉成任意长宽比。

### 4.2 港口插画与应用图标

Harbor 背景、吊机、码头和应用图标由内置 image_gen 制作，保留原始 PNG 母版及生成记录。通用空船 `spr_ship_empty` 采用原生像素 SVG 绘制，并由 `build-ship.cjs` 导出 PNG；空船内部几何可以在其 SVG 或脚本中修改。背景、船、吊机、码头可以作为独立组件组合。`home_harbor_layers.svg` 提供按组件组织的首页构图源：可以移动、缩放、调整各组件的层级和位置。

本版[首页构图 SVG](../02_可编辑源文件/Harbor/home_harbor_layers.svg) 内嵌背景、吊机、船、码头四个 PNG 组件，不依赖外部图片路径。其中生成插画仍是位图。单张吊机、背景或码头内部没有被自动拆成绳索、建筑等独立矢量图层，也不是逐像素矢量重绘。移动整艘船属于构图编辑；更改船的内部几何可回到独立的 `spr_ship_empty.svg` 或制作脚本；修改生成插画的内部造型则需要编辑位图母版或重新生成，再替换对应组件。每次替换源图后要同步更新 SVG 的内嵌内容；若后续改成链接位图，需连同相对路径对应文件一起分发。

插画具有像素风视觉，但生成图并非严格遵循同一个整数低分辨率网格；部分局部会有更细密像素、色阶或抗锯齿。不能将其描述为已经通过严格 pixel-perfect 验证。需要在实际显示尺寸下采用 Point 采样检查，必要时为目标显示尺寸另做人工像素整理。不能靠加一个 Pixel Perfect Camera 自动解决 UI 缩放与插画网格差异。

### 4.3 音频与字体源

音频重新合成应使用包内声音制作源与参数，保留事件含义、振幅控制和循环边界；详细采样率、声道、时长见最终清单。不要把有损压缩文件重新转成 WAV 当作无损原始源。

字体是现有许可字体的字集复用，不是本包新设计的完整字体。增加字符前先阅读第 8 节，不能仅修改 `ui-characters.txt` 就认为 TTF 已含有新字形。

## 5. PNG 导入规则

以下是后续导入 Unity 时的统一起点；本包没有执行这些工程操作。

| 选项 | 默认接入值 | 说明 |
| --- | --- | --- |
| Texture Type | Sprite (2D and UI) | UI 装饰、图标、货箱和船均按 Sprite 使用 |
| Sprite Mode | Single | 每个文件为独立交付图；需要 Atlas 时另做打包 |
| Mesh Type | Full Rect | 保留透明留白和矩形几何；避免 Tight 改变布局或裁切提示框 |
| Filter Mode | Point (no filter) | 所有交付 PNG 的默认像素采样起点 |
| Generate Mip Maps | 关闭 | UI 默认不生成 mipmap |
| Compression | 默认 None | 首先保证像素边缘与颜色；后续平台压缩须重新视觉验收 |
| Wrap Mode | Clamp | 防止边缘采到另一侧颜色；除清单明确可平铺者外不设 Repeat |
| Alpha | 使用源文件透明通道 | 不把棋盘格、白底或预览底色当作图像内容 |
| Sprite Pivot | 按最终清单 | 常见中心或底中心；船水线、底座和特效必须按对应项对齐 |
| Border | 按最终清单逐项填写 | 不套用一组猜测值；仅可拉伸组件设置 9-slice |
| Max Size | 不小于要保留的交付分辨率 | 防止导入器隐式缩小；平台优化后重新验收 |
| Pixels Per Unit | 使用一致的项目约定 | 本包以 Canvas UI 使用为主；不得把 PPU 当作安全区或点击尺寸 |

清单的 `width`、`height` 是导出 PNG 像素，`pivot` 是以左下角为原点的 0–1 归一化坐标；`border` 按 `[left, bottom, right, top]` 顺序记录 PNG 像素边界。9-slice 接入时按 Left、Bottom、Right、Top 四边分别填入，确认不会把切角、描边、装饰和内容安全区拉伸进中心。Unity `Image` 使用 Sliced，并检查小于推荐最小尺寸时是否边框挤压。货箱纹样、功能图标、船身和完整插画不能为了凑宽高随意使用 Sliced。清单 `border` 全零不表示可以任意拉伸。

通用空船的甲板线、货物安全矩形与船底对齐点见 `04_预览与验收/ship-manifest.json` 的 `anchors`。这些坐标采用图像左上角为原点；转换到 Unity 局部坐标时必须考虑 pivot、Y 轴方向和显示缩放，不应直接把图像 Y 值写成 RectTransform 的 anchoredPosition。

UI 继续使用现有 Canvas 体系，不安装或添加 Pixel Perfect Camera。该相机主要处理场景渲染，不能代替 Canvas 的布局、缩放和点击区域检查。中文 TMP SDF 的平滑轮廓与像素图不同：不要把字体图集强改为 Point，也不要用图像导入规则破坏 SDF 文本渲染。

显示尺寸和锚点尽量避免不必要的小数像素。Point 只是采样方式，不保证任意非整数缩放后每一条边都等宽。现有按下缩放与动效也要在真实 Canvas 下检查；必要的调整属于后续接入工作，不能以资产文件检查替代。

## 7. 布局 状态与输入合同

### 7.1 局内与关卡结构

局内自上而下保留：关卡/暂停 → 当前船和装载量 → 后两船预告 → 货堆 → 三格暂存 → 撤销/提示。短屏先缩装饰和间距，不能裁掉主要操作。默认三格暂存，规则层可能支持第 4 格，因此槽应是单个可复用组件，不能把“永远三格”的固定数字或三格整体装饰烘成不可扩展状态。

实际数据为 50 关与无尽模式，共用组件。选关每页最多 8 项，最后页只有 49/50。概念图中的 L06 箱序、01–10 岛屿布局均不能成为新数据。关卡按钮数字、完成状态、锁定状态必须绑定运行时数据。

当前船需求图标、船舱与数量分别呈现。船队页面只查看船序，不增加拖动排序或换船交互。箱堆最多六堆，每堆最高六箱，货箱可能重叠；六堆状态下每种纹样和顶箱点击区域仍应可辨。

### 7.2 视觉状态

| 对象 | 状态 | 表达要求 |
| --- | --- | --- |
| 按钮 | 默认、按下、禁用 | 按下反馈与禁用状态清楚；禁用不能只变色而仍可点击 |
| 货箱 | 顶部、被压、按下、提示、非交互影像 | 纹样在压暗和高亮后仍可辨；影像不接受点击 |
| 提示 | 可用、搜索中、已用完 | 使用动态文案/图标语义，不把“免费 1 次”固定画进按钮 |
| 关卡格 | 锁定、可玩、完成 | 锁、勾或明确文字；不单靠灰/蓝/绿区别 |
| 开关 | 开、关 | 滑块位置与图形/文字同步变化，含音效、音乐和减少动效 |
| 保存通知 | 正常、失败、重试中 | 失败时保留可点击重试入口，文字足够清楚 |
| 结果 | 完成、全部完成、真正卡住 | 结果文字不依赖动画；卡住呈现可恢复动作 |

暂存满时，若仍可合法取箱并装船，不应弹失败。真正卡住时优先提供撤销，也能重开或回首页；重开仍需确认。概念稿里的“暂存已满”警示不能覆盖这一规则。

### 7.3 输入与返回

所有背景、装饰、船体展示、碎片和飞行影像关闭不必要的 Raycast Target。按钮和顶箱显示区域应与热区一致；至少检查 44 屏幕像素的主要操作目标，不把 44 个 Canvas 参考单位误写成 44 个屏幕像素。

保留同箱按下/抬起才生效、拖动取消和单指归属；模态弹窗不能点穿。首页打开的设置/帮助返回首页，暂停打开的返回暂停。Escape 跟随当前页面返回，首页返回或桌面关闭进入退出确认。

## 8. 字体与中文

本包复用现有 `PortCargoUI.ttf`、`ui-characters.txt` 和 OFL 许可。原字体来自 Noto Sans SC，固定字重后子集化并改名。现有 TTF 的 cmap 有 330 个字符，其中中文码位 224 个；字符表有 330 个唯一字符。它不是完整中文字体，也不是新制作的像素字体。

本次 [font-coverage.json](../01_可交付/Fonts/font-coverage.json) 记录了对 Runtime 下 15 个 C# 文件字符串的只读检查：提取的 200 个不同中文字符在 TTF cmap 中缺失为 0。这个范围不包含未来文案、外部数据、Editor 文案，也不证明当前 TMP 图集或运行画面已经无缺字。新增文字仍需按下面步骤核对。

接入时沿用工程静态 TMP 字体方式。若没有新增中文，仍应把最终界面字符串与字符清单对照，并在真实文本布局中检查。若增加标题说明、错误文案、状态词或操作名，执行以下步骤：

1. 汇总首页、局内、全部弹窗、异常、教学及动态模板中的文字，包含标点、数字和符号。
2. 对照 TTF 字符映射，列出缺失字符；不要仅看字符清单长度。
3. 从许可允许的完整源字体重新生成覆盖所需字符的子集，保留 OFL、来源和名称约定。
4. 重建静态 TMP 图集；`Tools/RefreshUIFont.cs` 可作为工程现有流程参考，但本次未执行。
5. 检查全部字符串无方框、替代字形、溢出、截断或行高错位，再将字体资产恢复并保持为静态方式。

不使用在线字体掩盖缺字；不宣称未检查的新增文案已经“无缺字”。中文正文以可读性为先，像素气氛主要通过边框、图标、色块和插画表达。不要为了风格强制把所有中文降到不可读的位图尺寸。

## 9. 声音接入与混音

本包包含取箱、出港、通关、无效操作和菜单操作五类音效，以及 24 秒循环背景音乐。逐文件名称、采样率、位深、声道、时长和来源以清单与[字体与音频来源说明](../05_来源与许可/字体与音频来源.md)为准。接入映射如下：

| 本包文件，相对 `01_可交付/Audio/` | 现有引用或用途 | 要点 |
| --- | --- | --- |
| `SFX/pick.wav` | `pickClip` | 取箱 |
| `SFX/depart.wav` | `dockClip` | 出港；新文件名与工程旧 `dock.wav` 不同，不可漏绑 |
| `SFX/complete.wav` | `completeClip` | 通关 |
| `SFX/reject.wav` | `rejectClip` | 无效操作 |
| `SFX/menu.wav` | 可选菜单事件 | 需要后续显式绑定，不能声称复制文件后已经会播放 |
| `BGM/night_harbor_loop.wav` | `musicSource.clip` | 80 BPM、4/4、8 小节、24 秒；播放完整循环范围 |

WAV 母版为 44100 Hz / PCM16；音效单声道，BGM 双声道。音乐循环采样帧范围为 `[0, 1058400)`，不要复制最后一帧或额外裁去尾音。声音制作源为 `02_可编辑源文件/Audio/generate_audio_and_font_manifest.py`，依赖与重制步骤见音频来源说明。

背景音乐绑定现有 musicSource，开启 Loop，避免重复创建 Music AudioSource。工程现有结构为六个效果声源和一个音乐源，可继续复用。现有 BGM 音量起点约为 0.13，仅作接入时的参考；新素材响度不同，应实际试听后调整，不能机械沿用数值就断言响度一致。

混音与循环验收：

1. 先关闭 BGM，分别试听四种主要事件和菜单音，确认含义可区分、无削波或突发尖峰。
2. 开启 BGM，用取箱、连续出港、通关和拒绝反馈检查相对响度；BGM 不应盖过轻量操作反馈。
3. 使用现有 pitch 变化试听连续离港，不只听原始 WAV。
4. 对音乐至少听连续三次循环，检查第 24 秒回到开头时的点击、空隙、节拍跳动和尾音中断。文件边界数值检查不能代替听感。
5. 检查音效、音乐开关分别控制正确对象；退出设置、回首页和重启进程后仍保留设置。
6. 减少动效只影响反馈表现，不应误关声音，也不能让规则等待动画结束。

如果未来为首包体积进行压缩或采样率转换，应重新检查循环边界和音效瞬态。本包的声音交付不代表已经完成微信、iOS、Android 或目标设备混音验收。

## 10. 页面流程 保存与异常

换图不能改变当前流程合同：

- 闯关与无尽分别保留局面、撤销和提示；回首页不重置局面。
- 重开或替换未完成闯关先确认，取消后保留原局。

- 隐私与反馈保留本机保存说明、反馈所需关卡/程数/操作信息、版本和返回。
