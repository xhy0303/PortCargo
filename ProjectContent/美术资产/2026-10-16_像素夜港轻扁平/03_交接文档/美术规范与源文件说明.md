# 美术规范与源文件说明

视觉依据为包内 `05_来源与许可/风格依据_轻扁平版.png`。保留夜港蓝紫色调、琥珀灯光、阶梯轮廓；交互组件进一步减少体积，使用平色、细边和清楚的纹样。避免大面积高光、光晕、长投影和多层浮雕。

## 1. 配色与识别

| 用途 | 色值 | 使用说明 |
| --- | --- | --- |
| 深描边 / 深底 | `#0C1833` | 轮廓与最深背景 |
| 面板 / 船体深部 | `#142344` | 主深色表面 |
| 蓝色边框 | `#6485C2` | 面板细边、浅层结构 |
| 次按钮 | `#4672BC` | 次要可操作区域 |
| 主要动作 / 提示 | `#FFCF58` | 主按钮、提示框、选中状态 |
| 图标 / 浅文字 | `#EEF5FF` | 单色图标可通过 tint 调整 |
| R 货箱 | `#E54E59` | 浅色竖条 |
| B 货箱 | `#367BCE` | 九枚像素圆点 |
| G 货箱 | `#48AC76` | 平行斜线 |
| Y 货箱 | `#E8BD42` | 四枚十字 |

颜色与纹样同时表达货类。货箱大图和小图标来自同一形状源，四类轮廓与外侧留白一致。被压箱可在接入层压暗，但不可遮掉纹样。顶部高亮为浅色角框，提示为黄色角框，均保持中部透明。

## 2. 像素与尺寸

Cargo 基本逻辑网格为 32×32：大图导出 128×128，小图标 64×64。主次按钮逻辑为 96×32，导出 192×64。独立空船逻辑为 128×64，导出 512×256。各类 SVG 使用整数坐标及 crispEdges；详细规格见 [asset-manifest.json](../asset-manifest.json)。

精确组件除遮罩外使用二值 alpha；遮罩为 alpha 184 的均匀填充。港口生成插画含细密像素及少量透明过渡，不属于统一低分辨率像素网格。UI 与背景通过色系、轮廓和简化层次协调，而不是假定所有原图都使用相同像素尺寸。

缩放维持宽高比；Point 采样优先，实际 Canvas 下检查非整数缩放后的边宽变化。按钮和面板采用 9-slice。下面边界单位均为导出 PNG 像素，顺序为 **左、下、右、上**：

| 组件 | Border | 用法 |
| --- | --- | --- |
| 主/次按钮，全部状态 | 12 / 12 / 12 / 12 | 中心平色拉伸；文案另叠 |
| 通用/警告面板 | 16 / 16 / 16 / 16 | 高度由实际内容决定 |
| Toast | 8 / 8 / 8 / 8 | 重试入口是独立交互控件 |
| 开关轨道 | 8 / 8 / 8 / 8 | 滑块和开关语义独立 |
| 其他 | 0 / 0 / 0 / 0 | 不自动拉伸；货箱、船、图标保持比例 |

所有默认 pivot 为中心 `[0.5, 0.5]`，不要把 PNG 透明边裁去后仍沿用旧对齐参数。空船甲板上沿为图像 `y=156`，货物区域为 `x=160..464，y=32..156`，图像坐标原点在左上。详细锚点见 [ship-manifest.json](../04_预览与验收/ship-manifest.json)。

## 3. 背景裁切与图层

- 首页远景 `bg_home_harbor` 是 1536×1024，水面和天空合为一层。地平线约在上方三分之一，左右边缘可裁；背景不包含按钮或动态进度。
- 首页组件组合为背景、吊机、空船、码头四个独立组。`Harbor/home_harbor_layers.svg` 嵌入最终 PNG，移动整个 SVG 不会断图；`home-layout.json` 记录坐标与层级。
- 吊机为独立透明装饰，可在短屏隐藏或缩小。码头底部有意出血，允许被画面底边裁切。
- 局内背景 `bg_gameplay_harbor` 是 1024×1536。中心留给核心内容；竖屏居中 cover，左右约各 10% 可裁。边缘灯柱和系缆柱不表达玩法信息。不同长宽比必须检查，不允许用裁切背景的方式裁掉 UI。
- 应用图标母版为 1254×1254。平台发布规格在实际接入时另行确认，本次母版不是提交平台的认证导出。

插画没有 PSD 或逐建筑矢量图层。可以编辑位图母版、重新生成，或移动已拆出的组件。SVG 船、货箱、面板、图标、教程等内部图形可直接编辑。

## 4. 重建与维护

建议复制本包作为工作副本。Node.js 脚本需 `sharp`；Python 汇总脚本需 Pillow；音频脚本需 numpy 与 fontTools。依赖不随包打包，首次安装需要自行准备可用环境。

```sh
# 在工作副本根目录执行；会覆盖对应同名导出文件。
npm install --no-save sharp
python3 -m pip install Pillow
python3 -m pip install -r "02_可编辑源文件/Audio/requirements.txt"

node "02_可编辑源文件/build-components.cjs"
node "02_可编辑源文件/build-ship.cjs"
python3 "02_可编辑源文件/Audio/generate_audio_and_font_manifest.py"
python3 "02_可编辑源文件/build-delivery.py"
```

也可以通过 `SHARP_MODULE` 指定已安装的 sharp 模块位置。完整声音重制、单独重建音频和可选只读工程扫描，见[字体与音频来源](../05_来源与许可/字体与音频来源.md)。未提供工程路径时，不会重新证明旧工程文案覆盖；报告会注明跳过。

`build-components.cjs` 和 `build-ship.cjs` 为几何源权威；只编辑生成的 SVG 而不改脚本，下次重建会覆盖修改。插画 PNG 母版是位图源；替换时同步正式 PNG 与母版。首页构图的位置由 `build-delivery.py` 中 layers 数组定义，修改后重建 SVG、布局 JSON 和网页。

`build-delivery.py` 只读取 PNG 元数据和哈希，不修改位图像素。它重建总清单、网页数据、分层场景及界面预览；不能替代原始需求核对、手工看图、Unity 导入或设备测试。若改变数量、名称或需求，需同时修订 README、交接文档与页面说明。发布前重新生成验收报告和全包 SHA-256，不沿用本次检查结果。

## 5. 组装预览的边界

[组装预览](../04_预览与验收/组装预览.html) 使用本包真实 PNG，分别展示首页、局内、每页八项选关、设置与保存提示。文案、数字、状态由 HTML 独立叠加。开关只演示视觉变化，按钮不连接游戏业务；示例箱序与进度不作为关卡生产数据。视觉稿设计为 360×740 展示框，不能替代 320×568、360×800、720×1280 的真实 Unity 适配验收。
