# 《港口装箱》五套界面设计说明

日期：2026-10-15。用途：比较五种完整美术方向，选择后续界面方案。本次交付是独立设计稿，不是游戏工程更新；不包含可运行游戏、Unity 资源替换或手机验收。

## 1. 共同范围与现状边界

本批图版以首批 10 关为展示范围，覆盖可选全局首页、L06 局内初始画面、选关首屏，以及暂停设置、通关、僵局、按钮与箱子图样。选关图中的 01—10 是展示片段，不代表最终关卡总数上限。五版沿用相同规则与样例，便于比较视觉和信息组织，而不是比较不同玩法。

只读参考为工程 `Docs/README.md`、`GamePresenter.cs`、`HudView.cs`、`BoardView.cs` 和 `catalog.json`。读取时 README 与关卡文件为 10 关；Presenter 已出现无尽模式入口和“全部 50 关”文案，存在资料状态差异。因此本批不据此宣称 50 关已经确认，也不增加无尽模式专页。后续如实施，应先确认最终关卡范围和模式入口，再复用本方案的分页与弹窗体系。

现状为首次打开直接进入 L01，再次打开恢复当前棋盘和撤销历史。图版中的首页属于设计提案：可选择加入，也可保留直进局内；首页主按钮应根据真实状态显示“开始装船”或“继续第 06 关”。首页只承载开始、选关、设置及品牌场景，不新增签到、商店或任务。

现有核心规则：只取每堆顶部；与当前船同类则装船，其余进入默认三格暂存；满船后自动接下一船，并按暂存顺序寻找同类继续装载；撤销恢复整次动作；每局一次成功的免费提示；重开需要确认。界面不添加货币、倒计时、星级、账号和真实广告，也不把装载进度包装成分数。

## 2. 同一局面与操作层级

所有局内主图以 L06 初始状态为构图基准。精确合同为：左、中、右三堆从底到顶分别为 R/R/B、B/R/G、G/G/B；当前船 R×3，进度 0/3；后续 B×3、G×3；三格暂存为空。R 为竖条、B 为圆点、G 为斜线，Y 为十字。图版主要展示 R/B/G，Y 保留为组件扩展规范，不应出现在 L06 棋盘上。每类同时使用颜色与纹样，船标、货箱、暂存和队列保持一致。生成图属于美术概念稿，精确字稿、箱序与交互含义以本节及下文的合同为准。

竖屏阅读顺序为：关卡与设置 → 当前船需求及装载量 → 后续船队 → 货堆 → 暂存 → 撤销与提示。当前船是最高层级的信息锚点，货堆是最大操作区域。非顶部箱子可以看见，但必须比顶部弱一级；顶部使用描边、顶面亮度或边缘标记，不靠整体闪烁表达可点。

“后续船队”入口打开完整顺序；主画面只保留未来两艘。暂存区域始终明确三个槽位，即使为空也能读出容量。“撤销”在初始无历史时显示禁用；“提示”区分可用、查找中、已用完；提示只标记推荐的顶部箱，不自动代玩家操作。局面反馈文字应避开箱子和手指停留区域。

暂存满不等于立即失败：若堆顶还有当前船需要的货箱，仍可继续。只有不存在合法操作时才显示阻塞弹窗。暂存中的箱子由规则自动寻找匹配船装载，用户不能点击暂存手动腾位。撤销须完整回退一次点击及其引发的连续装船、出港，不是只让一个箱子飞回原处。

## 3. 01 软陶积木港湾

关键词是温暖、可触摸、轻松。奶油白 `#FFF5DF` 作底，珊瑚 `#F47968` 作主要行动色，湖蓝 `#57BFC4` 作海面，深棕 `#493D39` 作文字。场景采用玩具比例的立体船、短胖吊机和积木码头；箱子有柔软倒角、柔和接触阴影和略带手作感的表面。纹样压在箱子正面，不与材质噪点混淆。

首页以一座小型岛港占据中部，标题像立起来的玩具招牌，主按钮宽大而圆润。局内船与货堆形成前后空间，但货堆排布保持正面可数，不能让透视遮住下层种类。暂存做成三个浅凹托盘，空槽有柔和内阴影。选关是 10 个码头积木，使用清楚的编号、完成勾和锁，不用星星。

按钮建议 18–24 逻辑像素圆角，按下时轻微压低并减弱底部阴影；暂停是奶油色浮板，通关用小船离港和纸带，僵局用中性表情的救生圈标记。失败不整屏变红。适合强调亲切和轻度解谜；评审重点是立体装饰是否侵占棋盘、货箱是否仍能一眼数清。

## 4. 02 深海调度终端

关键词是秩序、精确、调度。深海军蓝 `#081B2C` 为主底，青色 `#66DAD4` 表示当前任务，信号橙 `#F5A044` 标记关键行动，灰蓝 `#91A9B8` 作次级信息。采用切角面板、细描边、工程网格、编号和清楚的刻度关系；辉光仅用于可操作边缘，不能覆盖中文和纹样。

首页是俯视港区调度台，中央航道连接装船区域，主操作像控制台上的实体键。局内将当前船做成顶部宽仪表：大号 0/3 与货类纹样并排，下方列出后续船序。货堆置于带列号的装卸区，三格暂存表现为明确的缓冲舱。选关采用两列五行任务清单，序号、状态、入口对齐，已锁定项目仍可读。

按钮使用切角轮廓和实心/描边层级；暂停为系统面板，通关标记“装船完成”，僵局保持“暂存已满”，不写“系统故障”。可加入一次短暂的装载确认扫描，减少动效时直接切换到静态高亮。适合强调规划感；评审重点是小屏细线是否足够清晰、暗底与三类货箱能否持续区分。

## 5. 03 复古航运票据

关键词是旅行、记录、印刷。暖纸 `#F1E4C9` 为底，油墨蓝 `#243D55` 作文字与轮廓，砖红 `#AA4939` 作主按钮和印章，少量芥黄用于货物区分。场景采用木刻或套色版画式港口插画，纸纹只铺在大块背景，文字和图样区域保持干净。

首页像一张航运海报：大标题、港湾插画、航次说明与横向票根按钮。局内的当前船信息成为“本船装载单”，货堆置于纸面码头，暂存为三个盖有编号的登记框。进度使用清楚的 0/3，不能用印章叠加来替代数字。选关是 10 张短票根组成的清单，完成状态盖“已完成”，锁定状态写“待解锁”。

按钮以票根、实线边框和套色块区分优先级，避免所有内容都做撕边。暂停像折页说明单，通关是一张盖章回执，僵局是一张提醒便笺。动效可用轻微落章和横向送单，减少动效时只显示印章结果。适合需要记忆点和叙事气质的版本；评审重点是印刷装饰是否降低文字辨识，以及纸张层次是否把真正可点的按钮藏起来。

## 6. 04 潮汐留白

关键词是安静、几何、清楚。暖白 `#F7F5EF`、近黑 `#16191B`、钴蓝 `#2458D9` 构成基调。采用瑞士现代主义的轴线、网格、非对称构图与大数字；二维平面船形和货箱轮廓取代材质与透视。不要堆叠圆角卡片，也不为每组信息都画底板。

首页以巨大“港口装箱”标题、单一几何船形、简洁菜单组成，留白参与构图。局内左侧或顶部显示大号“06”，当前船 0/3 是第二视觉重心；一条细线区分船区与棋盘，三堆货箱保持正面矩形，图样比阴影更重要。暂存采用三个开放方框。选关使用大编号清单或两列编号阵列，以小点、勾与文字标记状态。

主要按钮为钴蓝实心矩形，次要操作为文字加细线；暂停接近整洁的排版页，通关用“大勾 + 装船完成”，僵局用标题、说明和两个明确行动。动效限于短距离平移与透明度过渡。适合强调益智和品质感；评审重点是极简是否过度削弱点击线索，以及无彩色条件下纹样与层级是否仍然成立。

## 7. 05 像素夜港

关键词是夜色、街机、紧凑。深靛 `#171B39`、紫 `#7854AD` 与琥珀 `#FFC16E` 构成夜港，青蓝用于水面与次级提示。场景使用 16bit 像素语言、阶梯轮廓和有限色阶；灯光为离散像素亮区，不采用模糊渐变。中文正文优先保持可读，不能为追求像素风把字缩得过小。

首页是夜间码头横截面，灯塔、仓库和船舶分成少量层次，开始按钮像带硬边的街机选项。局内顶部是像素船与大数字装载量，货堆用统一像素模数组成，三格暂存是三个高对比停靠框。选关采用 10 个泊位节点，连接线只表达顺序，不能误导为分叉路线。

按钮使用阶梯外沿和单向高光，禁用时减少亮度并保留文字。暂停与通关使用厚边像素窗口，僵局窗口把“撤销”置于首选。可用两三帧水面、船尾灯和短促出港尾迹；减少动效时水面、灯光及提示全部静止。适合突出个性与游戏感；评审重点是像素缩放能否保持整数边缘，以及夜景细节是否抢走箱子图样。

## 8. 共用 UI 状态、恢复与文案

暂停标题“休息一下”，说明“先取顶部 · 同类装船 · 其余暂存”；功能包括继续、音效、音乐、减少动效、重新开始、选择关卡、隐私与反馈。开关应显示“开/关”文字，不只换颜色。全屏遮罩阻止误触棋盘，返回恢复原局面。

通关显示“装船完成”，主行动“下一关”，次行动“重玩本关”；首批全部完成时可改为“本批关卡已完成”，进入选关或重玩，避免用未确认的总关数。僵局显示“暂存已满”“试试撤销，换一个取箱顺序”，主行动“撤销”，次行动“重新开始”。不要把可恢复状态表现成永久失败。

重开确认：“重新开始？”“将从本关的第一箱重新开始”，按钮为“重新开始”“继续这一局”。提示已用完：“本局提示已用完，可撤销或重开”；未求得结果：“暂未找到”；无解反馈：“试试撤销”。锁定关卡：“通过前一关后解锁”。保存异常保留可点的“保存失败，点此重试”，成功后显示“进度已保存”。这些信息在五版中保持含义一致。

## 9. 竖屏、密集关卡与后续评审

设计参考竖屏 390×844 逻辑尺寸，关键文字建议不小于 14，操作目标建议至少 44×44，边缘留出安全区。先分配船区、棋盘、暂存和底部操作的真实空间，再填充场景。短屏优先压缩装饰与空隙，长屏增加呼吸空间，不能把重要按钮推出屏幕。

L10 为六堆、每堆四箱，共 24 箱，是密集适配必查状态。需要减少箱体装饰、收紧堆间距、保证每一层图样露出，并让顶部点击区保持可分离；不能简单等比缩到看不清。图版的 L06 不能替代 L10 适配验收。

若后续选定实施方向，先制作一套 L06、L10 与三种弹窗的实际尺寸样稿，再检查颜色与纹样、遮挡、单手点击、保存异常和恢复路径。五套只选择一套进入资源制作，避免混合圆润玩具、终端切角和票据撕边。常规动效建议控制在 120–300 毫秒；减少动效保留静态描边、数字更新和明确文案，取消弹跳、闪烁、相机移动与连续背景循环。本次未将这些建议写入工程，也未宣称完成运行或触摸验证。

## 10. 完整流程与补充状态

建议全局流程为：首次打开直接进入 L01 教程，或从可选首页开始；已有进度时继续当前局面；局内设置可进入选关或重开确认；成功进入下一关；阻塞优先撤销。首页的加入与否是独立产品决策，不影响五套视觉风格的成立。

| 状态 / 面板 | 内容与操作合同 | 视觉注意 |
| --- | --- | --- |
| 首关引导 | “点亮起的箱子”；只强调当前可点顶箱 | 不使用拖拽箭头，不让手势遮住图样 |
| 点击被压箱 | 高亮同堆顶箱，原局面不变 | 下层不是可点击按钮；不要画减分反馈 |
| 船队详情 | 从当前船起，按顺序列出货物纹样与容量；返回 | 只读列表，不画拖动把手或换序按钮 |
| 连续出港 | 单船“满载出港”；连续两船可显示“×2” | 属于动作反馈，不是货币或评分 |
| 提示成功 | 仅推荐一个顶部箱，保留玩家选择权 | 静态描边也要能表达，不依赖闪烁 |
| 暂存满但仍可操作 | 保留当前需求对应的可取顶箱 | 满槽变强调色即可，不弹失败遮罩 |
| 阻塞 | “暂存已满”；撤销 / 重新开始 | 撤销为恢复优先动作，重开仍需确认 |
| 重开确认 | “重新开始？”；重新开始 / 继续这一局 | 清楚标明会回到本关第一箱 |
| 全部关卡完成 | “全部通关”；选择关卡 / 重玩本关 | 总关数使用最终数据，不固化为 10 或 50 |
| 隐私与反馈 | 说明本机进度与设置存储；返回设置 | 不虚构账号、客服链接或联网统计 |
| 保存异常 | “保存失败，点此重试”；重试后“进度已保存” | 保留棋盘，不把保存失败画成关卡失败 |
| 恢复进度 | “已恢复上次进度”；可自动消失的轻提示 | 不要求用户重新开始 |

图版的设置与弹窗是样式样本，完整操作数量以此说明为准；空间不足时允许设置列表滚动，禁止把开关字号持续缩小。点击主要弹窗外的棋盘不应触发取箱。

## 11. 无尽模式与更多关卡的视觉延展

只读审查期间，工程源代码出现新增的无尽入口、“返回闯关”、“下一程”和按页选关逻辑，而关卡数据与旧 README 的范围未同步。这些变化不是本次设计任务写入，也不属于本次运行验证。主图维持固定 L06 基准，另以如下方式覆盖扩展界面，后续依据确认后的产品状态选择启用。

无尽模式入口可放在全局首页的次级操作区，以及暂停列表中；不抢占“继续”主操作。局内页头改为“无尽模式 / 第 N 程”，船、箱堆、暂存与操作按钮复用同一体系。成功弹窗改为“本程完成”，提供“下一程”“重玩本程”“返回闯关”；切换模式应恢复各自进度，界面不得暗示重置。选关超过首屏范围时分页或分段，不画 50 个极小目标。

| 风格 | 无尽入口 / 程数 | 更多关卡与完成弹窗 |
| --- | --- | --- |
| 软陶积木 | 小型环形航线浮标；“第 N 程”圆润数字牌 | 分组码头，上一组/下一组大按钮；完成沿用奶油浮板 |
| 深海调度 | “无尽调度”次级任务键，固定位置显示程数 | 任务清单分页；完成沿用仪表确认面板，避免假技术数值 |
| 复古票据 | “无尽航次”横向票根，程数作为航次编号 | 分页舱单；完成为回执，三个操作像三张清楚的票根 |
| 潮汐留白 | 简单文字入口，巨型数字保持同一基线 | 编号索引分页；完成页以标题和三项层级分明的文字/色块操作构成 |
| 像素夜港 | 像素航线图标，程数用可读数字标签 | 泊位分区切换；完成复用像素窗口，不加入无关生命值或分数 |

上述是视觉和交互延展建议，未生成额外独立无尽画板，未对模式可玩性、存档或全部关卡做验收。
