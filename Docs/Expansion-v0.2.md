# 50 关与无尽模式 · v0.2.0

依据 2026-10-15 用户新增要求实现：固定关卡共 50 关，另加无尽模式，先做简单测试；UI 视觉设计由另一个对话处理。原开发文档和首批关卡源文件保留。继续使用 Unity 6000.3.25f1，本机优先，微信后接。

## 游玩与进度

- 原 L01–L10 数据保留，新增 L11–L50。默认三格均可解，不需要广告。
- 每次通关解锁下一关；旧版本已通关 L10 的进度自动解锁 L11。
- 设置中的“选择关卡”每页八关，有上一页/下一页；未解锁项仅提示解锁条件。
- 设置中进入“无尽模式”。每程是一张独立小码头，完成后点“下一程”继续，没有最终通关页。
- 无尽每程 12–24 箱，难度采用逐步增加后回落的循环，后续部分轮次加入第四类货物。生成器按种子确定性构造，使用生产规则完整重放解序列后才交付棋盘。
- 闯关和无尽独立保留当前局面、撤销历史与提示使用情况。无尽设置中的“返回闯关”继续原关，重新进入无尽继续原程。重开只重开当前模式当前局，不重新随机刷局。
- 无尽继续采用默认三格、一次成功免费提示、撤销和重开；不新增倒计时、货币、榜单或广告。
- 每程保存完整关卡、种子、生成器版本和局面；以后更新生成器也按已存棋盘续玩。内部计数达到 int 上限时从新第一程继续，游戏本身不会结束。

## 代码与数据入口

`Assets/PortCargo/Data/Levels/catalog.json` 是运行时 50 关目录。`Core/EndlessGenerator.cs` 提供有界的确定性生成和解见证，独立于 Unity。`Core/ProgressValidator.cs` 校验两种模式的完整存档。`Runtime/GamePresenter.cs` 负责两模式切换、解锁和分页；HUD 只增加模式名称和程数，布局与视觉资源不重设计。

存档 envelope 继续使用 schema 1，载荷增加 `mode` 和 `endless`；`activeRun` 始终指闯关局。旧载荷没有新增字段时按闯关恢复。两模式共享原有 A/B 校验、回读和失败重试机制。

## 本轮验证范围

50 关全部做生产求解器求解与完整解回放；无尽抽样检查确定性、解回放与存档；独立开发包抽测关卡分页、L11/L25/L50、无尽连续三程及两个独立进程的续玩撤销。运行证据最终写入 `Evidence/v0.2/`。本轮按用户要求不做长时间压测、逐关人工难度校准或 UI 重设计。

自动可解不等于人类觉得难度合理。后续统一试玩重点是 L11 后难度是否合适、无尽重复感和不同布局的可读性。微信导出、真机和平台存储留到统一接入阶段。
