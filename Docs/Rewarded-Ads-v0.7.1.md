# 激励广告 v0.7.1 预加载优化

日期：2026-10-24。用户反馈每次点击观看广告后跳转较慢，本轮在已上传的 0.7.0 基础上优化等待路径。原广告奖励、免费玩法与存档约束见 [v0.7 接入记录](Rewarded-Ads-v0.7.md)，其构建和上传证据继续保留在 `Docs/Evidence/v0.7.0/`。

## 修改与行为

0.7.0 每次在玩家确认观看后才创建广告实例并调用 `Load`，加载成功后再 `Show`。0.7.1 将可提前完成的创建和加载移到后台；仅玩家主动确认后才展示广告。生产修改位于 [WeChatRewardedAds.cs](../Assets/PortCargo/Scripts/Platform/WeChatRewardedAds.cs)。

| 情况 | 0.7.1 行为 |
| --- | --- |
| 初始预加载 | `Configure` 后延迟 1 秒，再在可用的 `Update` 中分别加载额外提示和无尽跳程广告位；SDK 未就绪、组件不可用或 ID 无效时不启动对应预加载 |
| 两广告位缓存 | 每个广告位最多保留一个加载中或已就绪实例，使用独立 `multiton=true`；缓存不占全局展示锁，不会自动 `Show` 或发奖励 |
| 点击命中就绪缓存 | 直接对该实例调用 `Show`，省去本次点击后的创建和加载步骤；原生展示速度仍取决于微信与设备 |
| 点击命中加载中缓存 | 接管已有请求，不重复创建或 `Load`；沿用从最初开始加载计时的 20 秒 deadline，不把点击时间当作新起点 |
| 无缓存或缓存过期 | 使用新实例加载。本项目主动采用 300 秒作为缓存保鲜上限，已就绪缓存达到该上限时在点击时淘汰，不在后台定时轮换；这不是微信官方广告有效期。加载中缓存已超时也先淘汰再请求 |
| 后台失败 | 不调用游戏奖励回调、不弹游戏界面；等待 30 秒自动重试一次，第二次失败后停止自动重试，玩家仍可主动尝试 |
| 一次请求结束 | 释放已消耗实例，在后续 `Update` 补充该广告位缓存，不在关闭回调内同步创建；每次新实例都独立处理回调 |

后台缓存只有被玩家的显式 `Show` 接管后，才占用跨广告位、跨组件的全局展示锁。`Configure`、禁用和销毁会清理缓存及旧请求；先移除所有权再释放原生实例，迟到的加载、关闭或错误回调不能展示广告、发奖或影响新实例。

只有平台明确返回完整观看、且原有奖励票据仍有效时发奖。Loading 阶段仍可返回取消，Opening/Watching 阶段仍使用广告自身的关闭控件；20 秒加载、20 秒展示打开、180 秒等待观看结果的超时规则保留。原免费提示、撤销、重开、继续游戏、闯关进度和无尽规则均保持；本轮不新增强制广告或观看次数限制，也不变更两个广告位 ID。

预加载命中、加载状态与点击到展示的 `Trace` 诊断日志只在 `DEVELOPMENT_BUILD` 编译条件下输出。已有异常警告和微信 SDK 自身日志仍可能出现，“后台失败不弹界面”不表示控制台完全无错误日志。

## 真机验收边界

本轮可以确认代码提前加载，并在缓存命中时省去重复创建和加载；**尚无量化真机提速结果，不保证“秒开”**。首次尚未预加载完成、缓存超过 5 分钟、无填充或网络异常时仍可能等待或失败。

手机上仍需检查额外提示与无尽跳程的实际展示等待、重复观看、提前关闭、断网与恢复、切后台及奖励后的退出重启。0.7.0 的上传成功与模拟器记录不替代本轮产物或真机验收。
