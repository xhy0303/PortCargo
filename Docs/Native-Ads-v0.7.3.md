## 改动

- 首页保留原生横幅和完整港口组合画面，重新安排底部空间。原生横幅模拟器探测：请求 260 CSS 宽时实际为 300×104.4，存在最小宽限制。最终槽宽 302 CSS，额外吸收边界取整，不把 Unity 占位当作真实广告缩小。
- 暂停与设置新增横幅预留区，复用已有结算 ID；各页面有独立生命周期。
- 局内单格位于左上角独立空白区。关卡标题、标题底板与船体横向避让；棋盘、暂存区、暂停、船队、撤销和提示按钮不移动。加载失败或隐藏期间保持同一布局。
- 取箱、撤销和设置开关不结束当前广告访问；关闭或失败后，本次停留不反复请求。所有弹窗、激励广告、后台与保存失败均隐藏不适用的广告。
- 无广告、断网、加载超时和关闭不阻断免费流程，不发放额外奖励；既有自愿激励提示／跳程保持。
- Unity 场景旧“0 / 50”预览文字同步为“0 / 200”；实际关卡数一直由运行时数据载入。

## 单格尺寸证据及限制

模拟器创建及显示新单格广告后没有 onResize，也没有 style.realWidth / realHeight。截图可见包含“广告／关闭”区的整个组件约为68×110 CSS；代码只为本次已探测 ID 绑定保守80×120 CSS包围区，Unity槽为82×122 CSS。平台实际尺寸回调如有返回始终优先，超槽立即隐藏；不同 ID、未验证的模板不使用这个回退。

该配置对应当前后台单格模板。以后变更模板需重新测量。此模拟器测量不能替代手机端尺寸验收。证据见 [首页尺寸返回](Evidence/v0.7.3/wechat/home-size-probe.json)、[单格显示返回](Evidence/v0.7.3/wechat/grid-show-probe.json) 和 [单格截图](Evidence/v0.7.3/wechat/grid-size-probe.jpg)。这些是旧包模拟器中的单独组件探测，不是最终包截图。
